# Drishti AI

I built Drishti AI to check whether an image, video or piece of text has been edited or generated by AI. For images it runs 15 signal-processing checks (error level analysis, camera sensor pattern, JPEG block grid, noise, copy-move and others) plus one Hugging Face classifier, and combines them with a logistic regression I fitted on public datasets. The report shows each check, the weight it was given, and how much it counted. A result is a flag for a person to look at, never proof.

The old README and portfolio claimed 98% accuracy. That number was never measured and I have removed it. The numbers below are measured on images the model never saw, and they are much more modest.

## Run it

```bash
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env             # then edit: DJANGO_DEBUG=1 and a DJANGO_SECRET_KEY
python manage.py migrate
python manage.py runserver
```

Open http://127.0.0.1:8000. The first AI-generated check downloads `Organika/sdxl-detector` from Hugging Face. Uploads are checked (type, size up to 15 MB, real image decode, pixel limit), analysed in a temporary folder and deleted. Nothing is stored.

Tests: `pip install -r requirements-dev.txt` then `pytest` (39 tests: detectors on synthetic fixtures, upload validation, views, combiner maths, video and text on small inputs).

## Measured results

Two separate questions, two separate models. Both are logistic regression on the detector scores (standardised, L2, balanced classes, C chosen by 5-fold CV on the calibration split only). Seed 1337. Reproduce with `scripts/get_data.py`, `scripts/extract_scores.py`, `scripts/train_combiner.py` (see the top of each). Full numbers, per-detector AUCs and confusion matrices are in `metrics/*.json`; learned weights are in `image_module/weights/`.

### Task A: edited/spliced vs authentic

Data: CASIA v2.0 subset (2 authentic shards and 2 tampered shards; 1,024 authentic JPEG, 1,024 tampered of which 488 were JPEG and 536 TIFF originals), split 60% calibration / 40% test, random, stratified. External test: Columbia (363 images) and Coverage (200 images), never used for fitting. Source: Hugging Face mirror `ductai199x/image-manipulation-dataset-compilation` (all images re-saved as PNG, EXIF lost).

The first model I trained scored ROC AUC 0.80 on the CASIA test split. A baseline that only knows the original file extension and image size scored 0.82, so that number mostly measures "was this ever a JPEG". The shipped model is therefore trained and tested only on images whose original file was a JPEG (903 calibration, 609 test):

| Held-out test (CASIA, JPEG originals) | |
|---|---|
| ROC AUC | 0.83 (95% CI 0.79 to 0.86) |
| Accuracy | 0.74 (majority-class baseline 0.67) |
| Precision / recall | 0.57 / 0.79 |
| Recall by tamper type | splicing 0.82, copy-move 0.74 |
| Metadata-only baseline AUC | 0.63 |

External sets (different camera sources, TIFF originals): Columbia AUC 0.48, Coverage AUC 0.72 (accuracy about 0.5 on both). **The model does not transfer.** It learned traces specific to CASIA's JPEG processing. On Columbia it is at chance.

Per-detector AUC on the test split (0.5 is chance; below 0.5 means the check fires more on authentic images): CFA 0.76, copy-move 0.57, boundary 0.52, noise/median/frequency/reflection/geometric/EXIF 0.50 (no signal, weight zero), luminance 0.40, wavelet 0.46, JPEG grid 0.37, histogram 0.38, **ELA 0.28**. ELA is strongly inverted here: on this data authentic JPEGs light up more than the tampered ones, probably because of how CASIA's tampered files were re-saved. The learned weight for ELA is negative. That is a fact about this dataset, not a general rule.

### Task B: AI-generated vs real

Data: Tiny-GenImage (Hugging Face `TheKernel01/Tiny-GenImage`, CC BY-NC-SA 4.0): train shard 0 (2,000 images) for calibration, validation shard 0 (1,750 images, 875 real ImageNet JPEGs and 875 images from ADM, BigGAN, GLIDE, Midjourney, SD1.5, VQDM, Wukong) as test. Different real photos in each shard.

In this dataset real photos are JPEG at about 500 px and generated images are PNG at fixed sizes from 128 to 1024 px. A model that only sees file format and size gets AUC 1.0. To remove the format shortcut, every image is re-saved as JPEG quality 90 before the detectors see it (the app does the same). Image size remains a possible shortcut I could not remove.

| Held-out test (1,750 images, JPEG q90 control) | |
|---|---|
| ROC AUC | 0.90 (95% CI 0.88 to 0.91) |
| Accuracy | 0.82 |
| Precision / recall | 0.84 / 0.79 |
| Real images correctly passed | 0.85 |
| Recall by generator | ADM 0.98, BigGAN 0.97, GLIDE 0.92, Midjourney 0.72, VQDM 0.75, SD1.5 0.62, Wukong 0.60 |
| Metadata-only baseline AUC | 1.00 |

Because the size baseline is perfect, treat 0.90 as an upper bound for photos from other sources. I expect it to be lower on real-world images, and I have not measured that.

Hugging Face classifiers on the same test split (AUC): `Organika/sdxl-detector` 0.62 (0.74 without the JPEG control); `dima806/deepfake_vs_real_image_detection` 0.47, which is chance, so it is **dropped** from the combiner. The Swin classifier is kept because it improved cross-validated AUC on the calibration split by more than 0.01. Several detectors (CFA 0.18, frequency 0.25, noise 0.33) are strongly inverted on this data, which likely reflects resolution and resizing differences between ImageNet photos and generator output rather than anything about generation.

## What it is good at, and what it is not

- Good at: showing its work. Every flag lists the checks that drove it, their weights and the ELA heatmap, so a person can disagree.
- Reasonable at: flagging CASIA-style splices and copy-move in JPEG photos, and old-generation GAN or diffusion images of the kinds in GenImage.
- Not good at: anything outside those datasets. It is at chance on Columbia, weak on newer generators, and not tested on phone photos, social-media re-uploads, inpainting, or edits that were re-saved many times.
- Checks that need a face (eye highlights, symmetry, face boundary) carried no signal on these datasets and have zero weight. They are still in the code.

## Video and text: unvalidated heuristics

The video checks (blink rate, landmark jitter, optical flow, pulse signal, temporal noise, spectral spikes) and the text checks (a list of phrases and style rules) have not been benchmarked. The UI labels them as unvalidated. The video module uses the image models on sampled frames, which were trained on photos. The optional text web search sends the first long sentence to serper.dev and only lists hits; a hit is not proof of copying.

Nothing is committed; `scripts/get_data.py` downloads about 1.7 GB into `data/` (gitignored).

- CASIA v2.0, Columbia and Coverage via the Hugging Face mirror `ductai199x/image-manipulation-dataset-compilation`. The mirror has no licence field. ## Layout

`image_module/detectors/` the 15 checks. `image_module/pipeline.py` registry. `image_module/combiner.py` and `weights/` learned weights and explanation maths. `image_module/analysis.py` runs it for one file. `classifiers.py` the Hugging Face models. `video_module/`, `text_module/`. `scripts/` benchmark. `metrics/` results. `tests/`.
